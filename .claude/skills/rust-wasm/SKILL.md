# rust-wasm

The polynomial calculator's core is Rust, compiled to WebAssembly and called from a React component. This skill is the procedure for working on it.

## Layout

- `Cargo.toml` (workspace root), `rustfmt.toml`, `crates/`.
- `crates/polynomial/`: the pure Rust library. `lexer.rs` (tokens), `parser.rs` (recursive descent, grammar in its module comment), `ast.rs`, `eval.rs` (AST to polynomial), `polynomial.rs`, `rational.rs`, `format.rs` (TeX and plain text), `calculator.rs` (the entry point `calculate`), `error.rs`. Integration tests are in `crates/polynomial/tests/`.
- `crates/figure/`: the figure scene (JSON types, `parse_scene`, version policy, validation). Work on it test-first; the design is in `docs/graph-design.md`.
- `crates/figure/` also holds the engine: `expr/` (expression language), `compile.rs`, `sample.rs` (adaptive sampling), `arrow.rs` (Stealth, ported from pgf), `figure.rs` (the IR), `render.rs` (scene to IR), `tikz.rs` (TikZ output; the scene JSON is not embedded in it). The tests are in `crates/figure/tests/`; the TikZ golden file is in `tests/golden/`.
- `crates/figure-wasm/`: the wasm wrapper of `figure` (`parseScene`, `renderScene`, the typed `SceneOutcome`, `RenderOutcome`, `Figure`, all declared in the `typescript_custom_section`; keep them in step with the Rust structs, and note the snake_case of `line_width` and `line_end`). `mise run wasm` builds it next to the calculator, into `site/src/wasm/figure*`. The TypeScript side is `site/src/figure/` (`wasm.ts` loader, `svg.ts` IR to hast, `label.ts`, `samples.ts` samples for the check page, `wasm.test.ts`), the build-time plugin `site/src/plugins/rehype-figures.ts`, the React island is `site/src/components/figure/scene-checker.tsx`, and the hidden page is `dev/figure-scene.mdx`. `useLoaded` (`site/src/components/use-loaded.ts`) is the shared lazy-load hook.
- `crates/polynomial-wasm/`: the thin `wasm-bindgen` wrapper. It only converts values (`Outcome`) and declares the TypeScript types in a `typescript_custom_section`.
- `site/src/wasm/`: generated by `mise run wasm` (git-ignored). Never edit it.
- `site/src/calculator/`: `wasm.ts` loads the module lazily, `mathjax.ts` loads browser MathJax lazily, `highlight.ts` splits the input around an error.
- `site/src/components/calculator/`: the React island (`polynomial-calculator.tsx`, `math-view.tsx`, `use-calculate.ts`) and the page `site/src/content/docs/dev/calculator.mdx` (`client:load`).

## Commands

- `mise run wasm`: `cargo build --release --target wasm32-unknown-unknown -p polynomial-wasm`, then the `wasm-bindgen` CLI (`--target web`) into `site/src/wasm/`. `dev`, `build`, `sync`, and `test` depend on it, so generated files exist before type checking and linting.
- `mise run lint:rust`: `cargo fmt --check` and `cargo clippy --workspace --all-targets -- -D warnings`.
- `mise run test`: Vitest and `cargo test --workspace`. `mise run check` runs all of it.
- Native `cargo test` needs a linker (`gcc`, installed by the Dockerfile). The wasm build does not need it.

## Rules that are easy to trip on

- The `wasm-bindgen` CLI version (`mise.toml`) and the crate version (`=0.2.128` in `crates/polynomial-wasm/Cargo.toml`) must be identical, or the generated glue fails at runtime. Update both together.
- The CLI is installed by mise's `http` backend from a release URL, not the `github` backend: the GitHub API has a 60 requests per hour limit for unauthenticated calls, which the CI polling and Docker builds hit. Keep the per-platform URLs and run `mise lock --global` after a version change.
- Clippy runs with `pedantic` and denies `unwrap`, `expect`, `panic`, indexing, unchecked arithmetic, and `as` casts. Integer math uses `checked_*` and reports an error instead of overflowing. Tests get a crate-level `allow` for `expect` and indexing.
- A Rust identifier cannot contain `，` or start with a digit. Japanese test names must avoid Japanese punctuation and a leading digit.
- Spans in errors are counts of characters (Unicode scalar values), not bytes or UTF-16 units. The TypeScript side splits with `[...source]`, which iterates by code point. `wasm.test.ts` checks it with a surrogate-pair character.
- The parser has input and depth limits, and the polynomial has term and exponent limits (`MAX_INPUT_CHARS`, `MAX_DEPTH`, `MAX_TERMS`, `MAX_EXPONENT`), so no input can hang the tab or overflow the stack. A limit is reported as an error, never a panic (`panic = "abort"` in the release profile would turn a panic into an unreachable trap).

## The JavaScript contract

`serde-wasm-bindgen` turns a Rust `None` into `undefined`, not `null`, unless the serializer is `Serializer::new().serialize_missing_as_null(true)`. A TypeScript type of `T | null` needs that setting (`figure-wasm` uses it; `wasm.test.ts` caught the mismatch).

`Outcome` is a tagged union on `status` (`"ok"` or `"error"`); an expression error is a value, not an exception. The Rust `Outcome` (serde) and the TypeScript declaration in the `typescript_custom_section` must match. `crates/polynomial-wasm` has a test on the JSON shape and `site/src/calculator/wasm.test.ts` calls the built wasm. Change all three together.

## Browser MathJax

The calculator's result TeX is typeset in the browser with the same macros as the build-time pages (`@/math/macros`). The `tex-chtml.js` bundle is loaded with `import()` only when a result first needs it. MathJax's menu settings override the individual `enable*` options, so enrichment, speech, and braille are switched off through `menuOptions.settings`; otherwise it starts a speech worker that fails. Rendering is serialized because MathJax does not expect concurrent conversions. The readable label of a result is the plain-text form (`aria-label`); browser-side speech generation is not done.

## Tests at each layer

1. Rust unit tests in the modules (tokens, grammar, precedence, error spans, limits) and integration tests (identities, the binomial theorem, a round trip from `to_text` back through the parser on generated inputs).
2. The wasm crate's JSON shape test.
3. `site/src/calculator/*.test.ts` (Vitest): the built wasm called from Node, and the highlight helper.
4. `e2e/calculator.spec.ts`: typing, results, errors, full-width input, axe in the result and error states, no console errors. The all-pages specs cover the page too.

## Adding a feature

1. Put the logic in a library crate under `crates/` (a new crate per feature) and test it natively.
2. Add a thin `-wasm` crate with the typed contract, and a `mise run wasm` step for it.
3. Load it lazily from a small module in `site/src/`, and add a React island only for the interactive part.
4. Add a hidden `dev/` page, a link card on the home page, an E2E spec, and update `internals.mdx` and the code map in `CLAUDE.md`.

このページは，サイトの仕組みを人間が理解するための解説である．次の3点を中心に説明する．

- どこまでを，どの部品が担当しているか．
- 自分で実装したのは，どこか．
- それを利用するには，どう書き，どう変更するか．

書き方の一覧と動作確認は，`/math-study/dev/notation/`のページにある．Claude向けの手順と注意点は，`CLAUDE.md`と`.claude/skills/`にある．技術選定の理由と，確認した事実は，`docs/tech-decisions.md`(英語)にある．

## 全体像

記事は，MDXのファイルとして書く．ビルドのとき，Astroが次の順に処理して，静的なHTMLにする．

```text
MDXファイル(site/src/content/docs/**/*.mdx)
   │
   ▼  Astro(@astrojs/mdx)が読み込む
remark … Markdownの構文木を作る．remark-mathが，$…$を数式の節にする．
   │
   ▼  Markdownの構文木を，HTMLの構文木(hast)に変える
rehype … HTMLの構文木を書き換える
   ├─ rehypeStatements(自作)  定義，定理，式の番号付けと，参照の解決
   └─ rehypeMathjax(自作)     数式を，MathJaxでHTMLにする
   │
   ▼  Proof，Theoremなどのコンポーネントを組み立てる
Astro と Starlight … レイアウト，サイドバー，検索，ダークモード
   │
   ▼
静的なHTML，CSS，JavaScript(site/dist) → GitHub Pages
```

数式の描画，番号付け，参照の解決は，すべてビルドのときに終わる．ブラウザに届くのは，描画済みのHTMLとCSS，フォントである．MathJax本体は，ブラウザに読み込まない．

ブラウザで動く自作のJavaScriptは，折り畳みと補足の開閉だけである(`site/src/components/fold/auto-open.ts`)．検索やテーマの切り替えは，Starlightのスクリプトが行う．

## 部品の分担

| 領域                                                 | 担当する部品                                                         | 自作か                                   |
| ---------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------- |

| 文中の`$…$`と`$$…$$`の検出                           | remark-math                                                          | 既存                                     |

| MathJaxの呼び出し，CSSとフォントの配信，マクロ       | `site/src/math/`，`site/src/integrations/mathjax.ts`，`site/src/plugins/rehype-mathjax.ts` | 自作                                     |
| 定義，定理，式の番号と参照                           | `site/src/plugins/rehype-statements.ts`，`site/src/plugins/statements/` | 自作                                     |

自作したのは，既存の部品同士をつなぐ部分と，既存の部品にない機能である．MathJaxとAstroとStarlightの中身は，変更していない．

## 数式のしくみ

### 数式の流れ

1. remark-mathが，`$x$`と`$$…$$`を，`language-math`のクラスを持つ`code`要素にする．別行立ての式は，`pre`が包む．
2. `rehypeMathjax`が，すべての式を集め，TeXを1つずつ`renderer.ts`に渡す．
3. `renderer.ts`は，MathJaxを動かすWorker(`worker.ts`)へ，メッセージでTeXを送る．
4. MathJaxが，TeXをHTML(`mjx-container`)にし，読み上げ用の英語の文字列も作る．
5. `renderer.ts`が，読み上げ用の文字列を`aria-label`に移し，ブラウザで使わない属性を削る．`rehypeMathjax`が，`not-content`のクラスを付けて，文書の中の式を置き換える．
6. 全ページの処理が終わると，使った文字の分のCSSを，1つの`mathjax.css`にまとめて書き出す．数式のあるページだけが，このCSSを読み込む．フォントは，設定の読み込み時に`public/mathjax-fonts/`へ複製する．CSSの中身はデプロイのたびに変わるため，記事からのリンクには，ビルドごとに変わる`?v=`の印を付ける．付けないと，古いCSSが残ったブラウザで，新しい文字が崩れる．

### 自作した部分と，MathJaxの部分

MathJaxが担当するのは，TeXの解釈，HTMLの生成，導出木，読み上げ用の文字列である．自作したのは，それを使うための次の仕組みである．

| 自作の仕組み         | 内容                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| Worker               | MathJaxを，Astroの実行環境の外のスレッドで動かす．Astroの設定を読む一時的な環境が閉じた後でも，MathJaxを使える． |
| キュー               | Astroはページを並行して処理するが，MathJaxは同時の描画を想定していない．リクエストは，1つずつ送る．   |
| CSSとフォントの配信  | ビルドでは`dist/`へ書き出す．開発サーバーでは，同じURLで，その時点のCSSを返す．                        |
| エラーの扱い         | 未定義のマクロと構文の誤りを，行の位置つきのビルドの失敗にする．MathJaxの既定では，未定義のマクロが文字として描画される． |
| `not-content`の付与  | Starlightが本文の要素に付ける上の余白を，数式の内側で無効にする．付けないと，分数や上付き文字が離れて描画される． |
| キーボードでのスクロール | 別行立ての式は，長いと横にスクロールする．キーボードでもスクロールできるよう，`tabindex`を付けてフォーカスできるようにする． |
| 和文との隙間         | 和文の隣の行内の数式に，1/8emの隙間を入れる(`rehype-autospace.ts`)．本文の文字は，CSSのtext-autospaceが入れる． |
| マクロ               | `site/src/math/macros/`．分野ごとのファイルに分けている．数の集合は，LaTeXのnumbersetsパッケージに合わせた名前を持つ．                           |

Workerを使うのは，MathJaxを普通に読み込むと，Astroの設定を読む一時的な環境が閉じた後に，読み込みに失敗するためである．Workerを終了することで，ビルドのプロセスも終了できる．

### 和文との隙間

TeXでは，和文と欧文の間に，`\xkanjiskip`という隙間が自動で入る．原稿にはスペースを書かず，組版のときに入れたいので，サイトでも同じ仕組みを用意している．

- 本文の和文と欧文，数字，インラインコードの間は，CSSの`text-autospace: normal`が，1/8emの隙間を入れる．句読点の隣には入らない．
- 数式は独立した箱で，`text-autospace`の対象にならない．そこで，ビルド時に，`rehype-autospace.ts`が，行内の数式の前後の文字を調べる．漢字，ひらがな，カタカナの隣なら，クラスを付ける．CSSは，そのクラスを，同じ1/8emの余白にする．
- 文字は増やさないため，コピー，検索，読み上げには影響しない．コードブロックと，数式の内側は，対象から外している．

### マクロ

マクロは，`site/src/math/macros/modules/`の下に，分野ごと(数の集合，位相，線型代数など)のファイルとして，意味の分かる名前で定義する．マクロの短縮名は作らない．`macros/index.ts`が，`modules/`の下のファイルをすべて集めるため，新しい分野は，ファイルを置くだけで使える．同じ名前を複数のファイルで定義すると，ビルドが失敗する．数の集合は，`\RealNumbers`のように書き，`\RealNumbers[bfup]`で書体を選べる．

MathJax 4には`\csname`がなく，マクロでは，引数の値から別のマクロの名前を組み立てられない．そのため，書体の切り替えは，環境の名前(`\begin{numbersetstyle…}`)を使う，回り道で実現している．

## 定義，定理，式番号のしくみ

### 番号付けの流れ

MDXの`<Theorem>`などの要素は，rehypeの構文木に，そのまま残る．`rehypeStatements`は，その要素と，数式の`\label`を読み，次の順に処理する．

1. ページの識別子を決める．frontmatterの`pageId`があればそれを，なければファイル名を使う．
2. `Definition`，`Lemma`，`Proposition`，`Theorem`，`Corollary`を，文書の順に数え，「定理abs-3」のラベルと，リンクの飛び先(アンカー)を決める．要素には，`label`と`anchor`の属性として渡す．見た目は，Astroのコンポーネントが作る．
3. `\label{識別子}`のある別行立ての式に，連番を付ける．`\label`を取り除いて，MathJaxの`\tag{abs-1}`を加え，式を包む要素に`id`を付ける．番号の描画は，MathJaxが行う．
4. `<Ref />`を，ラベルの文字を持つリンク(`<a>`)に置き換える．`<Proof of="…">`の題名を，その定理のラベルにする．
5. 別のページの定理や式を参照するときは，`catalog.ts`が作る一覧を引く．

### ほかのページの参照

Astroは，ページを並行して処理し，プラグインには，1ページずつしか見えない．そこで，`catalog.ts`が，`content/docs/**/*.mdx`をすべて読み，各ページの番号付きの要素の一覧を作る．ファイルの更新時刻を覚えていて，変わったファイルだけを読み直す．開発サーバーでも，編集が反映される．

一覧の作成と，ページの変換は，同じ関数(`findStatementNodes`，`numberPageItems`)を使う．このため，両者の番号は，必ず一致する．

### ラベルの規則

- ラベルは，種類，ページの識別子，連番をつなげた形である(「定理abs-3」，「式(abs-1)」)．
- 連番は，ページごとに1から数える．定義から系までは共通の連番で，式は別の連番である．
- ページの識別子は，サイト全体で一意にする．重なるとビルドが失敗する．そのため，章立てを決めなくても，ラベルが一意になる．
- ページの識別子は，frontmatterの`pageId`で，短縮名にできる．ラベルと，`Ref`の`page`属性は，その短縮名を使う．
- 定理や式に`id`を付けると，アンカーがその`id`になる．定理を挿入して連番が変わっても，リンクは壊れない．

### 自作の理由

remark-mathは，式に番号を付けない．MathJaxの自動採番は，式を1つずつ描画する今の方式に合わない．未来の式への参照を解決できず，未定義の参照は，エラーとして扱われず，そのまま描画される．ほかのページの番号を引く機能は，どちらにもない．そのため，番号付けと参照の解決は，`rehypeStatements`が行う．

### 制約

- 番号を付けられる式は，段落から独立した別行立ての式(`$$…$$`)で，`\label`が1つのものだけである．複数行に分けるときは，`aligned`で1つの式にまとめる．
- 式の中の`\ref`と`\eqref`は使えない．参照は，本文の`<Ref />`で書く．
- ほかのページから参照されるページは，ファイル名を，小文字の英数字，ハイフン，アンダースコアにする．Starlightが作るURLと，一致させるためである．

## 折り畳みと補足のしくみ

`Proof`と`Remark`は，HTMLの`details`要素で，JavaScriptなしでも開閉できる．`Detail`は，文の途中に置く補足で，JavaScriptが有効なときだけ，切り替えのボタンが現れる．無効なときは，常に表示される．

ブラウザで動くのは，`auto-open.ts`である．次の場合に，閉じている折り畳みと補足を開く．

- URLのハッシュが，その中の要素を指しているとき．
- 検索でハイライトされた語が，その中にあるとき．
- 印刷するとき．

折り畳みの中の定理や式も，ハッシュで指せば，その折り畳みが自動で開く．

## 計算機のしくみ

多項式の計算機(`/math-study/dev/calculator/`)は，式を入力すると，展開した式と，変数ごとの偏微分を表示する．式の解析と計算は，Rustで書き，WebAssembly(Wasm)にして，ブラウザで動かす．

### 流れ

```text
入力欄(React) → Wasm(Rust) → 結果のTeXと平文 → 数式の描画(ブラウザのMathJax)
```

1. 利用者が入力欄に式を書くと，Reactの部品(`polynomial-calculator.tsx`)が，Wasmの`calculate`を呼ぶ．
2. Wasmの中で，Rustの`polynomial`クレートが，字句解析，構文解析，評価をして，展開した多項式にする．そして，変数ごとに微分する．
3. 結果は，TeXと平文の2通りの文字列で返る．誤りのときは，説明と，入力の中の位置が返る．
4. Reactの部品が，TeXを，ブラウザのMathJaxで描画する．ビルド時に描画する記事の数式と，同じマクロを使う．

### 役割分担

| 領域                                     | 担当する部品                                                                   | 自作か                 |
| ---------------------------------------- | ------------------------------------------------------------------------------ | ---------------------- |
| 式の解析，展開，微分，TeXと平文の出力    | `crates/polynomial/`(Rust)                                                     | 自作                   |
| RustをWasmにして，JavaScriptから呼ぶ橋   | `crates/polynomial-wasm/`(自作)と，wasm-bindgen(既存のCLIとクレート)           | 窓口は自作             |
| Wasmの読み込み，ブラウザのMathJaxの読み込み | `site/src/calculator/`                                                      | 自作                   |
| 入力と表示                               | `site/src/components/calculator/`(React)                                       | 自作                   |
| Rustの道具                               | Rustの本体，cargo，rustfmt，clippy．miseが版を固定する                         | 既存の道具に，自作の設定 |

Rustの核は，ブラウザにも，Astroにも依存しない．そのため，`cargo test`だけで，式の意味を確かめられる．

### Rustの核の作り

- 字句解析(`lexer.rs`)：入力を，数，変数，記号に分ける．全角の記号と数字は，半角にそろえる．
- 構文解析(`parser.rs`)：再帰下降法で，構文木にする．文法は，このファイルの先頭のコメントにある．
- 評価(`eval.rs`)：構文木を，展開した多項式にする．
- 多項式(`polynomial.rs`)：係数は，正確な分数で持つ．足し算，掛け算，累乗，微分を持つ．
- 出力(`format.rs`)：全次数の大きい順に並べて，TeXと平文にする．平文は，そのまま式として読み戻せる．

数は，128ビットの整数の分数で持つ．あふれるときは，停止せずに，誤りとして返す．入力の長さ，括弧の深さ，結果の項の数，指数にも，上限がある．

### 使える式

- 足し算，引き算，掛け算，割り算，累乗，括弧が使える．
- 変数は，英字1文字である．掛け算の記号は，変数か開き括弧の前でだけ，省略できる．
- 割る数は，0でない定数に限る．指数は，0以上で100以下の整数に限る．

### 計算機の変更

1. `crates/polynomial/`を変更し，`cargo test`で確かめる．
2. Wasmの窓口(`crates/polynomial-wasm/`)の型を変えたときは，Rustの`Outcome`と，TypeScriptの型の宣言を，同じに保つ．
3. `mise run wasm`で，Wasmを作り直す．`mise run check`と`mise run dev`は，先に自動で行う．
4. 表示を変えたときは，`e2e/calculator.spec.ts`を通す．

手順の詳細は，`.claude/skills/rust-wasm/SKILL.md`にある．

## 図のシーンのしくみ

図は，シーンと呼ぶJSONのデータから作る．シーンをRustで読み込んで検査し，描画の中間表現にして，SVGとTikZに書き出す．最初の図は，`/math-study/dev/figure-first/`にある．空間の図(球と座標軸，球の面の上の円)は，`/math-study/dev/figure-space/`にある．確認用のページ(`/math-study/dev/figure-scene/`)では，シーンを入力して，読み込みと検査の結果とTikZの出力を見られる．設計の全体は，`docs/graph-design.md`にある．

### シーンの読み込みの流れ

```text
シーンのJSON
  → Wasm(Rust)：読み込み，検査，式の評価，標本化
  → 中間表現(線，矢じり，ラベル)
  → SVGとラベル(ビルド時，記事の中)と，TikZの文字列
```

- 記事に`<Figure src="図の名前" />`と書くと，ビルド時に`site/src/figures/図の名前.json`を描画して，図に置き換える(`rehype-figures.ts`)．線と矢じりはSVGである．ラベルはSVGの上に重ねる．文字と数式が混ざった文字列を1つの数式にして，記事の数式と同じMathJaxが描画する．
- 図は，平面の図と空間の図に分かれる(シーンの`view`の形で決まる)．空間の図は，方位角と仰角の平行投影で描く．球は不透明な殻として扱い，球に隠れた線の部分は，点線(既定)か破線にする．隠れ方は，点から見る側への視線が球に当たるかで判定し，切り替わる点を二分法で詰める(`space.rs`)．
- 曲面(`surface`)は，2つの変数の式で書き，三角形の網にして，輪郭と隠れ方を求める(`surface.rs`)．曲面は不透明な殻として，軸と曲線を隠す．輪郭は，視線が曲面に接する所を，網の辺の上で補間して結ぶ．網は，細かさ(`mesh`)を上げると，滑らかになるが重くなる．
- 点，ベクトル，線分は，空間の図でも使える．座標は3個で，曲面や球に隠れる部分は，隠れた部分の線で描く．隠れた点の印は，描かない．
- 交線(`intersection`)は，2つの曲面が交わる曲線である．2つの網の三角形が交わる線分を，空間の格子で相手を絞って求め，端が重なるものをつないで線にする．
- `<Figure>`に`id`を書くと，図に「図ページの識別子-連番」の番号が付き，`caption`の説明文が図の下に置かれる．番号は，定義や定理と同じ番号付けの段階(`rehype-statements.ts`)で決め，`<Ref>`で参照できる．
- ベジエ曲面は，`surface`の`bezier`に制御点の網を書くと作れる．式の曲面と同じ網にして，同じに扱う(`bezier.rs`)．式で書けない自由な形の曲面を，制御点を動かして作れる．
- 方位角と仰角を動かせる図(`components/projection/`)は，同じRustのエンジンをブラウザで動かして描く．図のSVGは，ビルド時に使う`figureToHast`の結果を，Reactの要素にして表示する．ラベルは，ブラウザのMathJaxで組む．向きから作る基底は，`projection/camera.ts`にもあり，エンジンの投影と一致することを，テストで確かめている．
- 切り口と交線は，網から求めたあと，点を厳密な式の上へ磨く(Newton法)．隣り合う点の中点も磨き，弦から離れていれば点を足し，直線とみなせる点は間引く．そのため，曲がりの強い所だけ点が密になり，網の粗さによらず滑らかである(`refine.rs`)．
- これらの数学的な原理(投影，隠れ方，輪郭，交線，Newton法，斜線)は，実装に立ち入らない解説として，`/math-study/dev/figure-algorithms/`にまとめてある．平面の図の塗りつぶしは，`/math-study/dev/figure-fill/`にある．図の方法を変えたときは，この解説も合わせて直す．
- 切り口(`cut`)は，曲面を平面(法線と定数)で切った線である．網の各頂点で平面の式の値を求め，符号が変わる辺を補間して結ぶ．輪郭を求める処理と同じ形で，切り口は曲面の網の上にぴったり乗る．
- 平面の図では，グラフと曲線を，見える範囲で切り取る(`clip.rs`)．範囲を出る所で線が終わり，戻る所から新しい線が始まるので，どちらの出力にも，切り取りの指定はいらない．軸は，`range`を書けば，見える範囲の外へも延ばせる．
- 線の色と太さは，`style`の`color`と`width`で選ぶ．色は名前(`gray`，`red`，`blue`，`green`，`orange`，`purple`)で，SVGでは，明るい背景と暗い背景で見やすい色に置き換わる(`figure.css`)．TikZでは，`xcolor`の名前になる．
- 点(`point`)は，座標を数か式で持ち，あとに置くオブジェクトの式から，`<id>_x`と`<id>_y`の名前で参照できる．ほかの点から決める点(平行四辺形の頂点や，中点)は，点の式(`"B + C - A"`，`"(A + B) / 2"`)で書ける．点の式は，点のidを位置ベクトルとして，和と差と数の倍でつなぐ．`vector`と`segment`は，点のidで2点を結ぶ．ベクトルは，終点に矢じりを持つ．
- 領域(`region`)は，2つのグラフ(かグラフとx軸)に挟まれた部分を，平行な斜線で埋める(`hatch.rs`，`region.rs`)．斜線の位置は，原点から数えた間隔の倍数で決まり，内側の判定は偶奇規則である．斜線は，見える範囲で切り取られる．`fill`を書くと，領域を薄い色で塗れる(不透明度つきの塗りつぶしの要素で，どちらの出力にも出る)．
- 格子は，`grid`オブジェクトで置く．`x_step`と`y_step`の刻みで，見える範囲を区切る細い点線である(平面の図だけ)．
- 座標軸の目盛は，軸の`ticks`に，位置と名前を並べて書く．目盛は軸に直角な短い線で，名前は，x軸では下，y軸では左に置き，`anchor`でずらせる．位置には，媒介変数と定数を使った式も書ける．
- 座標軸の矢じりは，TikZの`Stealth`と同じ形で，pgfのソースから移した．点線と破線の寸法も，TikZと同じにしてある．
- TikZの出力は，手で直さない．出力は，手元で`mise run tikz`が，LuaLaTeXでコンパイルして，SVGの図と重ねて比べる(CIでは実行しない)．線と矢じりは，0.5mm以内で一致する．ラベルは，書体の細かい違いと，箱の高さの違いで，数pxのずれを許している．ラベルの文字の大きさは，TikZの既定に合わせて10ptである．図を直すときは，シーンを直して，出力し直す．出力の先頭のコメントに，元のシーンが入っているので，出力から元のシーンを取り出せる．

- シーンは，図の入力だけを持つ．点，媒介変数，式，スタイルであり，計算した値は持たない．将来のGUIが，JSONの値を1つ書き換えるだけで，点やスライダーを動かせるようにするためである．
- シーンは，それを書いたアプリケーションの版(`version`)を持つ．エンジンは，主版が同じで，自分より新しくない版のシーンを読む．
- 誤りは，例外ではなく，値で返る．種類の名前と説明に加えて，原因のオブジェクトの`id`か，JSONの構文の誤りの行と列が付く．

## 図の作成ページのしくみ

図の作成ページ(`/math-study/figure-editor/`)は，サイドバーに出る公開ページである．オブジェクトを足して設定すると，シーンのJSONができ，記事の図と同じエンジンがブラウザで描く．シーンのJSONの読み込みと書き出し，対応するTikZのダウンロードもできる．

### 図の作成の流れ

```text
フォームの入力
  → シーンの下書き(JSON，誤りがあっても持てる)
  → Wasm(Rust)：読み込み，検査，描画，TikZ
  → プレビュー(SVGとラベル)と，TikZの文字列
```

- 下書き(`site/src/figure-editor/draft.ts`)は，エンジンが読むJSONと同じ形である．オブジェクトを足す，並べ替える，取り除く操作を持つ．検査はエンジンに任せる．誤りは理由とオブジェクトのidが返るので，プレビューの下に示して，そのオブジェクトを選べるようにする．
- 新しいオブジェクトの初期値は，`defaults.json`にある．種類ごとの入力欄の一覧は，`fields.ts`の表である．種類を増やすときは，この2つと，`create.ts`の`OBJECT_TYPES`に足す．エンジン側の検査は変えなくてよい．
- 入力欄は，種類ごとの小さいコンポーネント(`field-basic.tsx`と`field-special.tsx`)にして，`field.tsx`が仕様の種類から選ぶ．値の読み書きの規則は，テストしやすいように，`values.ts`に純粋な関数として置いた．
- 編集中の図は，ブラウザの`localStorage`に保存する．サーバーの描画と揃えるため，保存した図は，最初の描画のあとで読む．
- シーンのJSONは，ファイルとして読み込む，書き出す．TikZは，`tikzpicture`の断片(`.tikz`)と，LuaLaTeXでそのままコンパイルできる単体の文書(`.tex`，`tikz-document.ts`)を書き出せ，クリップボードへコピーもできる．
- 見本は，記事で使っているシーン(`site/src/figures/`)を，そのまま読み込む(`samples.ts`)．平面と空間の，両方の見本がある．
- 空間の図では，プレビューをドラッグして，方位角と仰角を動かせる(`use-drag-rotate.ts`)．ポインタを押した要素がポインタを捕える(`setPointerCapture`)ので，指やポインタが外へ出ても追える．横のドラッグが方位角，縦のドラッグが仰角を動かす．方位角と仰角が，どちらも数のときだけ効く(式で書かれていれば，ドラッグでは変えられない)．方位角は畳み込み，仰角はエンジンの上限(90度)で止める(`draft.ts`の`rotateView`)．
- シーンのJSONの形式は，[JSON Schema](https://enunun.github.io/math-study/schema/scene.schema.json)で決めている．図の作成ページからもリンクする．スキーマで表せない規則(範囲の大小関係，オブジェクト間の参照，識別子の重なりなど)は，スキーマ自身の`description`に，「スキーマでは表せない」と書いて示す．

### 編集中の図と，プレビューの分け方

ドラッグで見る向きを変えられるようになると，1つの図を，操作する画面と，出力の確認に同時に使うのは無理が出てきた．そこで，「編集中の図」と「プレビュー」の2つに分けた(`figure-editor.tsx`の`Body`，`preview.tsx`，`output-preview.tsx`)．どちらも，同じシーンを，別々にRustのエンジンで描く(`use-figure-renders.ts`の`useFigureRenders`)．

- 「編集中の図」は，ドラッグでき，読みやすさのための補助を加えて描く．格子と座標軸は，実際に描かれるオブジェクトと見分けやすいよう，補助のスタイル(灰色の点線)で描く．平面の図の座標軸には，きりのいい間隔の目盛も足す(空間の図の軸は，まだ目盛に対応していない)．この補助は，シーンのJSONを表示専用に組み立て直すだけで，実際の出力には影響しない(`edit-scene.ts`の`buildEditScene`)．背景にも薄い色を付け，補助の点線を，実際に点線や破線で描いたオブジェクトと見分けやすくする(`.fe-edit-preview`)．
- 「プレビュー」は，補助を含まない，実際の出力(TikZやJSONの書き出し)と同じ図である．ドラッグはできない．
- 編集の補助が原因で描けなくなったとき(表示専用の組み立てに誤りがあったとき)は，「編集中の図」も，補助なしの図に自動で戻す．そうしないと，ユーザーが作っていない項目の誤りを見せてしまう．

### 曲面と球のワイヤーフレーム，ベジエ曲面の制御点の網

曲面(`surface`)は`wireframe`，球(`sphere`)も`wireframe`，ベジエ曲面はさらに`control_net`を持てる(いずれも`Style`と同じ形で，あれば描き，スタイルとして使う)．編集中の図だけの見た目ではなく，シーン自身の項目である．実際の出力(プレビューとTikZ)にもそのまま現れ，書式(色，線の種類，太さ)も選べる．フォームでは，チェックボックスで項目自体の有無を選び，チェックすると，そのスタイルの入力欄が現れる(`ToggleStyleInput`)．

- ワイヤーフレームは，曲面の上に引いた，`u`一定・`v`一定の断面の線である．式で書いた曲面でも，ベジエ曲面でも，同じ`SurfaceMap`(2つの変数から空間の点を返す関数)を使うので，同じ描き方になる(`space.rs`の`surface_wireframe_items`)．球は，経線と緯線を引く(`sphere_wireframe_items`)．どちらも，軸や曲線と同じ，隠れ方で分けて描く手順(`wireframe_line`，`split_by_visibility`)を使う．
- 制御点の網は，ベジエ曲面だけが持てる項目である．曲面の上の線ではなく，制御点そのものを，行と列で結んだ折れ線である(`control_net_items`)．曲面の形を決める，元の点を確かめるためのもので，ワイヤーフレームとは別に選べる．

### 図の作成の制約

- 図をドラッグして動かせるのは，空間の図の見る向きだけである．点の位置は，数か式で入力する．
- 元に戻す操作は，まだない．JSONの書き出しが，バックアップの代わりになる．
- TikZのラベルの位置は，プレビューと少しずれることがある．

## 検査と公開

| 対象                             | 道具                | コマンド                  |
| -------------------------------- | ------------------- | ------------------------- |
| コードと文書の整形               | oxfmt(MDXを除く)    | `mise run fmt`            |
| TypeScriptなどのコード           | oxlint              | `mise run lint:code`      |
| Rustのコード                     | rustfmtとclippy     | `mise run lint:rust`      |
| MDXの構文と構造                  | remark-lint         | `mise run lint:mdx`       |
| READMEと`docs/`のMarkdown        | markdownlint        | `mise run lint:markdown`  |
| 日本語の文章                     | textlint            | `mise run lint:text`      |
| 型                               | `astro check`       | `mise run check`に含む    |
| 単体テスト                       | Vitestとcargo test  | `mise run test`           |
| ブラウザでの動作                 | Playwright          | `mise run e2e`            |
| アクセシビリティ                 | axe(Playwright経由) | `mise run e2e`に含む      |
| リンク切れ，404，コンソールエラー | Playwright          | `mise run e2e`に含む      |
| 見た目の確認                     | Playwrightの撮影    | `mise run screenshot`     |
| 上のすべてとビルド               | すべて              | `mise run check`          |

`mise run check`は，CIと同じ内容である．コミットのときは，lefthookが，ステージしたファイルだけを検査する．`main`にpushすると，GitHub Actionsが`check`とE2Eを実行し，どちらも成功すると，GitHub Pagesへ公開する．E2Eが失敗すると，公開されない．

MDXの検査には，ビルドと同じ構文木で読むremark-lintを使う．閉じていないタグや，式の誤りは，コミットのときに見つかる．

### ブラウザでの自動検査

E2Eには，機能ごとの検査に加えて，次の検査がある．対象のページは，ビルドしたサイトから自動で集めるため，ページを足しても，検査は自動で広がる．

- すべてのページを，ライトとダーク，広い画面と狭い画面で，axeで検査する．違反は1件でも失敗にする．折り畳みは，開いてから検査する．
- すべてのページを開き，コンソールのエラー，読み込みの失敗，4xxと5xxの応答がないことを確かめる．
- すべての内部リンクの飛び先と，`#見出し`の飛び先が，存在することを確かめる．外部リンクは，検査しない．

見た目の崩れは，自動で検査しない．フォントや描画が環境で違うため，スクリーンショットの比較は誤検出しやすい．数式や書式を変えたときは，`mise run screenshot`で目視する．検査するブラウザは，Chromiumだけである．

## 使い方

### 記事の書き方

書き方は，`/math-study/dev/notation/`のページに，例つきでまとめてある．コード例と描画結果を並べてあるので，そのまま写して使える．

### 記事の追加

1. `site/src/content/docs/`の下に，分野ごとのディレクトリを作り，その中に`.mdx`を置く．ファイル名は，小文字の英数字とハイフンにする．ほかのページから参照するときに，URLが一致するためである．
2. 新しい分野のディレクトリは，`site/astro.config.ts`の`sidebar`に，グループとして足す．`{ label: '解析学', items: [{ autogenerate: { directory: 'analysis' } }] }`の形である．既存の分野に足すだけなら，設定は要らない．開発用のページ(`dev/`)は，サイドバーと検索に出さないが，トップページから，リンクをたどれるようにする．
3. frontmatterの`title`と`description`を書く．定理や式の番号に使うページの識別子は，指定がなければファイル名になる．長いときは，`pageId`で短くする．
4. 定義や定理，証明は，`notation`のページの書き方に従う．`dev/continuity.mdx`が，一通りの記法を使った例である．

### マクロの追加

1. `site/src/math/macros/modules/`の下に，分野ごとのファイルを置く．既存の分野なら，そのファイルに足す．ファイルは，`MacroModule`をdefault exportする．統合のファイルは，変更しない．マクロは，意味の分かる名前で定義する．
2. `notation.mdx`の「自作マクロ」の一覧に，1行足す．
3. 単体テスト(`rehype-mathjax.test.ts`)に，展開の例を足す．

### 定義と定理の種類の追加

1. `site/src/plugins/statements/collect.ts`の`STATEMENT_KINDS`に，要素の名前と，ラベルの先頭の語を足す．
2. `site/src/components/statement/`に，既存のものと同じ形のコンポーネントを足し，`index.ts`から出す．
3. `.markdownlint-cli2.jsonc`の設定は不要である．MDXは，remark-lintが検査するため，登録は要らない．

### コンポーネントの追加

Astroのコンポーネントとして，`site/src/components/`に置く．中に，隣り合う独自要素を並べるときは，Starlightの余白の規則を避けるため，`not-content`のクラスを付ける．MDXに書く要素の追加は，`notation.mdx`に，例と動作確認を足す．

### 困ったときの対処

| 症状                                     | 原因と確認する場所                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| ビルドが，数式で失敗する                 | メッセージに，ファイルの行とTeXがある．未定義のマクロか，構文の誤りである．                            |
| ビルドが，参照や識別子で失敗する         | メッセージに，ファイルの行と理由がある．指す先がない，重複，使えない文字のどれかである．               |
| コミットが，MDXの検査で止まる            | 閉じていないタグや，式の`{…}`の誤りである．`mise run lint:mdx`で，位置を確認できる．                   |
| 分数や導出木の規則名がずれる             | Starlightの余白が，数式の内側に及んでいる．`not-content`のクラスが付いているか確かめる．               |
| 計算機が古い，またはWasmがない           | `site/src/wasm/`は，生成されたファイルである．`mise run wasm`で作り直す．`check`，`build`，`dev`は，先に自動で行う． |
| cargo testで，リンカが見つからない       | `gcc`が要る．Dockerfileで入れる．コンテナを再構築するまでは，`apt-get install gcc libc6-dev`で入れる． |
| 数式のフォントが読み込めない             | フォントは，Astroの設定を読み込むときに，`public/mathjax-fonts/`へ複製される．開発サーバーやビルドを，起動し直す． |

## 折り畳み

### 読み込み

MDXのフロントマターの直後に、次の1行を書きます。

```mdx
import { Proof, Detail } from '@/components/fold';
```

### 証明: `<Proof>`

証明の詳細を隠すときに使います。

```mdx
<Proof title="定理1.2">

ここに証明を書きます。Markdownをそのまま書けます。

- 箇条書き
- コード`x + 1`

</Proof>
```

<Proof title="定理1.2">

ここに証明を書きます。Markdownをそのまま書けます。

- 箇条書き
- コード`x + 1`

</Proof>

### 補足: `<Detail>`

行間を埋める補足に使います。

```mdx
<Detail title="なぜ成り立つか">

補足の本文です。

</Detail>
```

<Detail title="なぜ成り立つか">

補足の本文です。

</Detail>

### 属性

| 属性    | 既定    | 説明                                                                 |
| ------- | ------- | -------------------------------------------------------------------- |
| `title` | なし    | 文字列です。ラベル(「証明」「補足」)の後ろに表示する題名になります。 |
| `open`  | `false` | 真偽値です。指定すると、開いた状態で表示します。                     |

`open`の例です。

```mdx
<Proof title="最初から開いている証明" open>

本文です。

</Proof>
```

<Proof title="最初から開いている証明" open>

本文です。

</Proof>

### 入れ子

折り畳みの中に、折り畳みを置けます。

```mdx
<Proof title="外側の証明">

外側の本文です。

<Detail title="内側の補足">

内側の本文です。

</Detail>

</Proof>
```

<Proof title="外側の証明">

外側の本文です。

<Detail title="内側の補足">

内側の本文です。

</Detail>

</Proof>

### 注意

中身をMarkdownとして解釈させるには、タグの前後に空行が必要です。空行がないと、中身は文字列のまま表示されます。

## 動作確認の項目

- Tabで証明・補足の行にフォーカスが移り、EnterまたはSpaceで開閉できます。
- 下の折り畳みの中にある「かたつむり」をCtrl+Fで検索したとき、ヒットした折り畳みが自動で開くかどうかは、ブラウザによって異なります。
- [折り畳みの中の見出しへ移動](#折り畳みの中の見出し)を押すと、その折り畳みが開きます。ページを開き直して、末尾に`#折り畳みの中の見出し`を付けたURLを開いても、同じです。
- 印刷のプレビューで、閉じた折り畳みの中身も出力されます。
- スクリーンリーダーでは、「証明」に続けて「定理1.2」と読み上げられ、開閉の状態も伝わります。

## 文章の規則と検査

コミット時とCIで、`site/src/content`のMarkdownとMDXを、textlintとmarkdownlintで検査します。

- 和文と欧文の間、和文とインラインコードの間には、スペースを入れません(「MDXの記法」「`mise run dev`を実行」)。
- 見出し、本文、箇条書きを、ですます調にそろえます。
- 太字とコロンを使った箇条書きや誇張した表現など、AIが書いたように見える書き方を避けます。
- 見出しの階層を飛ばさず、リストの前後に空行を入れます。MDXで使うコンポーネントは、`.markdownlint-cli2.jsonc`の許可リストに追加します。

検査と修正のコマンドです。

```sh
mise run lint:text
mise run lint:markdown
pnpm exec textlint --fix site/src/content
```

最後のコマンドは、自動で直せる指摘(スペースなど)だけを直します。MDXでは`textlint-disable`のコメントが効かないので、誤検出は書き方を変えて避けます。

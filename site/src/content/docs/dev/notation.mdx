## 折り畳み

### 読み込み

MDXのフロントマターの直後に，次の1行を書く．

```mdx
import { Detail, Proof, Remark } from '@/components/fold';
```

### 証明：`<Proof>`

証明の詳細を隠すときに使う．

```mdx
<Proof title="定理1.2">

ここに証明を書く．Markdownをそのまま書ける．

- 箇条書き
- コード`x + 1`

</Proof>
```

<Proof title="定理1.2">

ここに証明を書く．Markdownをそのまま書ける．

- 箇条書き
- コード`x + 1`

</Proof>

### 補足：`<Detail>`

行間を埋める補足に使う．文の後ろに置く．閉じているときは文の後ろに「［…］」が付き，押すと補足が続けて現れる．

```mdx
実数の二乗は0以上である．<Detail>実際，正の数の二乗は正であり，負の数の二乗も正である．0の二乗は0である．</Detail>
```

実数の二乗は0以上である．<Detail>実際，正の数の二乗は正であり，負の数の二乗も正である．0の二乗は0である．</Detail>

句点は，補足に含まれない．補足の前の文には，書き手が句点を書く．補足の中には，複数の段落や式のような，1行に収まらない内容は置けない．

### 長い補足：`<Remark>`

複数の段落やリストが要る補足に使う．枠付きの折り畳みで，証明と同じように開閉する．

```mdx
<Remark title="なぜ成り立つか">

補足の本文である．

</Remark>
```

<Remark title="なぜ成り立つか">

補足の本文である．

</Remark>

### 属性

| 属性    | 対象              | 既定    | 説明                                                         |
| ------- | ----------------- | ------- | ------------------------------------------------------------ |
| `title` | `Proof`，`Remark` | なし    | 文字列．ラベル(「証明」「補足」)の後ろに表示する題名になる． |
| `open`  | すべて            | `false` | 真偽値．指定すると，開いた状態で表示する．                   |

`open`の例．

```mdx
<Proof title="最初から開いている証明" open>

本文である．

</Proof>
```

<Proof title="最初から開いている証明" open>

本文である．

</Proof>

### 入れ子

証明や長い補足の中に，折り畳みを置ける．

```mdx
<Proof title="外側の証明">

外側の本文である．

<Remark title="内側の補足">

内側の本文である．

</Remark>

</Proof>
```

<Proof title="外側の証明">

外側の本文である．

<Remark title="内側の補足">

内側の本文である．

</Remark>

</Proof>

### 注意

`Proof`と`Remark`は，中身をMarkdownとして解釈させるために，タグの前後に空行が必要である．空行がないと，中身は文字列のまま表示される．`Detail`は文の途中に書くので，空行を入れない．

閉じている`Detail`の中は，ブラウザ内検索の対象にならない．JavaScriptが無効な環境では，`Detail`は常に開いた状態で表示される．

`Detail`の切り替えボタンは，補足の本文の後ろに置かれる．文が「〜である．実際〜．」と続けて読めるようにするためである．

数式は，ビルド時にMathJaxで描画する．行内の式は`$…$`，別行立ての式は`$$…$$`で書く．

```mdx
任意の$x \in \RealNumbers$について，$\abs{x} \ge 0$が成り立つ．
```

$$

### 自作マクロ

マクロは，`site/src/math/macros/modules/`の下に，分野ごとのファイルとして定義する．定義を変えたら，次の一覧も更新する．

- `\NaturalNumbers`，`\Integers`，`\RationalNumbers`，`\RealNumbers`，`\ComplexNumbers`：自然数，整数，有理数，実数，複素数の全体の集合である．名前は，LaTeXのnumbersetsパッケージに合わせている．
- `\NumberSet[スタイル]{N}`：任意の文字を，数の集合の書体で組む．
- `\abs{x}`：絶対値である．
- `\norm{v}`：ノルムである．
- `\set{…}`：波括弧で囲んだ集合である．
- `\lparen`，`\rparen`：半開区間の片側の丸括弧である．$\lparen a,b]$のように書く．
- `\rank`：階数の演算子名である．
- `\openball{a}{r}`：中心$a$，半径$r$の開球である．
- `\closure{A}`：集合$A$の閉包である．
- `\preimage{f}{U}`：写像$f$による集合$U$の逆像である．
- `\colored{色}{式}`：式の一部に，図と同じ色を付ける．色の名前は，図の`style.color`と同じ，`gray`，`red`，`blue`，`green`，`orange`，`purple`である．暗い背景では，図と同じく明るい色になる．

数の集合の書体は，`[…]`の引数で選ぶ．書体は，黒板太字の`bb`，立体の太字の`bfup`，斜体の太字の`bfit`で，省略すると`bb`になる．

```mdx
$\RealNumbers$，$\RealNumbers[bfup]$，$\RealNumbers[bfit]$，$\NumberSet[bfup]{K}$
```

$\RealNumbers$，$\RealNumbers[bfup]$，$\RealNumbers[bfit]$，$\NumberSet[bfup]{K}$

```mdx
$\colored{red}{x} + \colored{blue}{y}$
```

$\colored{red}{x} + \colored{blue}{y}$

定義のないマクロや，構文の誤りは，ビルドの失敗になる．失敗した式は，ファイルの行と列，元のTeXとともに表示される．

### ベクトルの書き方

ベクトルは，斜体かつ太字の小文字で書き，`\boldsymbol{d}`とする．成分は，角カッコの行列に並べる．列ベクトルを基本とし，行ベクトルは，成分を`&`で区切って，カンマは入れない．

```mdx
$$
\boldsymbol{p} = \begin{bmatrix} x \\ y \\ z \end{bmatrix}, \qquad \boldsymbol{p}^{\mathsf{T}} = \begin{bmatrix} x & y & z \end{bmatrix}
$$
```

$$
\boldsymbol{p} = \begin{bmatrix} x \\ y \\ z \end{bmatrix}, \qquad \boldsymbol{p}^{\mathsf{T}} = \begin{bmatrix} x & y & z \end{bmatrix}
$$

点や座標も，同じ書き方にする．区間や関数の引数，パラメータの組は，丸カッコのままでよい．

### 導出木

`bussproofs`の記法で書く．前提は`\AxiomC`，結論は`\UnaryInfC`，`\BinaryInfC`，`\TrinaryInfC`で書き，規則の名前は`\RightLabel`か`\LeftLabel`で付ける．

```mdx
$$
\begin{prooftree}
  \AxiomC{$A$}
  \AxiomC{$A \to B$}
  \RightLabel{$\to$-E}
  \BinaryInfC{$B$}
\end{prooftree}
$$
```

$$
\begin{prooftree}
  \AxiomC{$A$}
  \AxiomC{$A \to B$}
  \RightLabel{$\to$-E}
  \BinaryInfC{$B$}
\end{prooftree}
$$

シーケントは，`\AxiomC{$\Gamma \vdash A$}`のように，前提と結論を1つの式として書く．`\fCenter`を使う書き方は，描画はされるが，読み上げ用の文字列が作られない．

### 読み上げ

式の読み上げ用の文字列は，英語で作られ，`aria-label`に入る．日本語のロケールはないため，式の中の日本語(`\text{…}`)は，1文字ずつ読まれる．導出木は，前提の中身が読み上げられない．`\norm`は，「metric」と読まれる．

### 数式の動作確認

- 式が，フォントの読み込みを待たずに崩れることなく表示される．ライトとダークの両方のテーマで，式が読める．
- 行内の式は，本文の行の高さを大きく乱さない．
- 幅の狭い画面では，導出木や長い式を，横にスクロールして読める．
- 式のあるページだけが，`mathjax.css`を読み込む．
- 和文の隣の行内の式は，前後に1/8emの隙間が入る．句読点の隣には，隙間が入らない．

## 定義と定理

定義と定理には，ビルド時に番号が付く．番号を使って，同じページや，ほかのページから参照できる．

### 定理の読み込み

定義，補題，命題，定理，系，例，問題，解答は，それぞれ`Definition`，`Lemma`，`Proposition`，`Theorem`，`Corollary`，`Example`，`Problem`，`Answer`である．使うものを，フロントマターの直後に読み込む．参照の`Ref`は，読み込まずに使える．

```mdx
import { Answer, Corollary, Definition, Example, Lemma, Problem, Proposition, Theorem } from '@/components/statement';
```

### 番号と参照

番号は，種類とページの識別子と連番をつなげた「定理abs-3」の形である．連番は，ページの中で，種類をまたいで1から数える．

```mdx
<Definition id="even-number" name="偶数">

整数$n$が偶数であるとは，ある整数$k$が存在して$n = 2k$と書けることをいう．

</Definition>

<Theorem id="even-square">

偶数の二乗は偶数である．

</Theorem>

<Proof of="even-square">

偶数$n = 2k$に対して，$n^2 = 2 \cdot 2k^2$である．

</Proof>

<Ref to="even-number" />を使った<Ref to="even-square" />は，<Ref page="abs" to="triangle-inequality" />と同じように参照できる．
```

### 定理と参照の属性

| 要素                    | 属性   | 説明                                                                                             |
| ----------------------- | ------ | ------------------------------------------------------------------------------------------------ |
| `Definition`などの8種類 | `name` | 見出しに添える語句．括弧に入れて表示する．                                                       |
| `Definition`などの8種類 | `id`   | 参照とアンカーに使う識別子．省略すると，アンカーは連番のラベルになる．                           |
| `Ref`                   | `to`   | 参照する定義，定理，式の`id`．                                                                   |
| `Ref`，`Proof`          | `page` | ほかのページを指すときの，ページの識別子．省略すると，同じページを指す．                         |
| `Proof`                 | `of`   | 証明する定理の`id`．指定すると，証明の題名が「定理abs-3」になる．`title`とは同時に指定できない． |

識別子は，英数字で始め，英数字，ハイフン，アンダースコアだけを使う．`id`は，ページの中で一意にする．連番は，定理の挿入や並べ替えで変わる．外部からのリンクや参照を固定したい定理には，`id`を付ける．`id`を付けた定理のアンカーは，連番が変わっても変わらない．

### ページの識別子

ページの識別子は，frontmatterの`pageId`で指定する．指定がなければ，ファイル名を使う(`index.mdx`は，ディレクトリの名前)．サイト全体で一意にする．重なると，ビルドが失敗する．

このページの識別子は，ファイル名の`notation`である．参照先の`abs`も，ファイル名である．ページをまたぐ参照は，参照先のファイル名を，小文字の英数字，ハイフン，アンダースコアにする．Starlightが作るURLと一致させるためである．

### ラベルの短縮

ラベルには，ページの識別子が入るため，識別子が長いと，ラベルも長くなる．frontmatterの`pageId`に短縮名を書くと，ラベルと，`Ref`の`page`属性の両方で，その短縮名を使う．たとえば，`dev/continuity.mdx`は，`pageId: cont`と書き，ラベルは「定理cont-7」の形になる．短縮名は，サイト全体で一意にする．

## 式番号

別行立ての式に`\label{識別子}`を書くと，ページの識別子と連番の番号が付き，本文から参照できる．`\label`のない式には，番号が付かない．

```mdx
$$
\int_0^1 x^2 \, dx = \frac{1}{3} \label{integral-square}
$$

<Ref to="integral-square" />は，<Ref page="abs" to="abs-cases" />と同じように参照できる．
```

$$
\int_0^1 x^2 \, dx = \frac{1}{3} \label{integral-square}
$$

<Ref to="integral-square" />は，<Ref page="abs" to="abs-cases" />と同じように参照できる．

### 式番号の書き方

- 番号は，式の右に「(notation-1)」の形で表示する．参照の文字は，「式(notation-1)」の形である．
- 連番は，`\label`のある式だけを，ページの中の文書の順に数える．定義や定理の連番とは別に数える．
- 識別子は，定義や定理と同じ書き方にする．同じページの定義や定理の識別子とも，重ならないようにする．
- 参照は，本文の`<Ref />`で書く．式の中の`\ref`と`\eqref`は，MathJaxが，未定義の参照を，エラーにせず描画してしまうため，ビルドの失敗にする．
- `\label`は，段落から独立した別行立ての式(`$$…$$`)に，1つだけ書ける．複数行の式は，`aligned`で1つの式にまとめる．行内の式に書くと，ビルドの失敗になる．
- `<Proof of="…">`には，式の識別子を指定できない．

### 式番号の動作確認

- 上の例の式の右に，「(notation-1)」が表示される．
- 例の中の2つの参照が，「式(notation-1)」と「式(abs-1)」のリンクになる．後者は，`/math-study/dev/abs/`の定義の式へ移る．
- 幅の狭い画面でも，番号のある式が，ページを横にあふれさせない．

## 文章の規則と検査

コミット時とCIで，`site/src/content`のMarkdownとMDXを，文章はtextlintで，MDXの構文と構造はremark-lintで検査する．

- 和文と欧文の間，和文とインラインコードの間，和文と数式の間には，スペースを入れない(「MDXの記法」「`mise run dev`を実行」「点$a$と」)．表示では，1/8emの隙間が自動で入る．
- 本文と箇条書きは，常体(である調)にそろえる．
- 和文の後ろのコロンは，全角の「：」にする．後ろにスペースを入れない．
- 読点は全角のコンマ「，」，句点は全角のピリオド「．」にする．`、`と`。`は使わない．
- 太字とコロンを使った箇条書きや誇張した表現など，AIが書いたように見える書き方を避ける．
- 見出しの階層を飛ばさず，リストの前後に空行を入れる．MDXで使うコンポーネントの登録は要らない．閉じていないタグや，式の誤りは，ビルドの前にremark-lintが見つける．

検査と修正のコマンドは次のとおりである．

```sh
mise run lint:text
mise run lint:markdown
pnpm exec textlint --fix site/src/content
```

最後のコマンドは，自動で直せる指摘(スペースなど)だけを直す．MDXでは`textlint-disable`のコメントが効かないので，誤検出は書き方を変えて避ける．

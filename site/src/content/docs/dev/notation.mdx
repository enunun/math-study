## 折り畳み

### 読み込み

MDXのフロントマターの直後に、次の1行を書く。

```mdx
import { Proof, Detail } from '@/components/fold';
```

### 証明：`<Proof>`

証明の詳細を隠すときに使う。

```mdx
<Proof title="定理1.2">

ここに証明を書く。Markdownをそのまま書ける。

- 箇条書き
- コード`x + 1`

</Proof>
```

<Proof title="定理1.2">

ここに証明を書く。Markdownをそのまま書ける。

- 箇条書き
- コード`x + 1`

</Proof>

### 補足：`<Detail>`

行間を埋める補足に使う。

```mdx
<Detail title="なぜ成り立つか">

補足の本文である。

</Detail>
```

<Detail title="なぜ成り立つか">

補足の本文である。

</Detail>

### 属性

| 属性    | 既定    | 説明                                                         |
| ------- | ------- | ------------------------------------------------------------ |
| `title` | なし    | 文字列。ラベル(「証明」「補足」)の後ろに表示する題名になる。 |
| `open`  | `false` | 真偽値。指定すると、開いた状態で表示する。                   |

`open`の例。

```mdx
<Proof title="最初から開いている証明" open>

本文である。

</Proof>
```

<Proof title="最初から開いている証明" open>

本文である。

</Proof>

### 入れ子

折り畳みの中に、折り畳みを置ける。

```mdx
<Proof title="外側の証明">

外側の本文である。

<Detail title="内側の補足">

内側の本文である。

</Detail>

</Proof>
```

<Proof title="外側の証明">

外側の本文である。

<Detail title="内側の補足">

内側の本文である。

</Detail>

</Proof>

### 注意

中身をMarkdownとして解釈させるには、タグの前後に空行が必要である。空行がないと、中身は文字列のまま表示される。

## 動作確認の項目

- Tabで証明・補足の行にフォーカスが移り、EnterまたはSpaceで開閉できる。
- 下の折り畳みの中にある「かたつむり」をCtrl+Fで検索したとき、ヒットした折り畳みが自動で開くかどうかは、ブラウザによって異なる。
- [折り畳みの中の見出しへ移動](#折り畳みの中の見出し)を押すと、その折り畳みが開く。ページを開き直して、末尾に`#折り畳みの中の見出し`を付けたURLを開いても、同じである。
- 印刷のプレビューで、閉じた折り畳みの中身も出力される。
- スクリーンリーダーでは、「証明」に続けて「定理1.2」と読み上げられ、開閉の状態も伝わる。

## 文章の規則と検査

コミット時とCIで、`site/src/content`のMarkdownとMDXを、textlintとmarkdownlintで検査する。

- 和文と欧文の間、和文とインラインコードの間には、スペースを入れない(「MDXの記法」「`mise run dev`を実行」)。
- 本文と箇条書きは、常体(である調)にそろえる。
- 和文の後ろのコロンは、全角の「：」にする。後ろにスペースを入れない。
- 太字とコロンを使った箇条書きや誇張した表現など、AIが書いたように見える書き方を避ける。
- 見出しの階層を飛ばさず、リストの前後に空行を入れる。MDXで使うコンポーネントは、`.markdownlint-cli2.jsonc`の許可リストに追加する。

検査と修正のコマンドは次のとおりである。

```sh
mise run lint:text
mise run lint:markdown
pnpm exec textlint --fix site/src/content
```

最後のコマンドは、自動で直せる指摘(スペースなど)だけを直す。MDXでは`textlint-disable`のコメントが効かないので、誤検出は書き方を変えて避ける。
